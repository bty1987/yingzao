# 10 - 插件开发指南(从零到上架)

> **本文是什么**:第三方开发者视角的插件开发全流程指南——以 `addons/addon-example`(请假示范工程)与真实业务插件(addon-member 最接近示范体量)为抄作业对象,把架构军规、装配机制、设施清单串成一条可执行路径。**配合阅读:`docs/02-插件框架RFC.md`(机制设计)、`AGENTS.md`(军规全文)**。
> 状态:2026-10-23 第 77 次运行整理(基于 16 个已落地插件的经验反推)。

---

## 一、一个插件是什么(30 秒版)

一个 Maven 模块 + 六类东西,放进 `addons/addon-<id>/`:

```
addons/addon-<id>/
├── pom.xml                                                    # 依赖 addons-api + core
└── src/main/
    ├── java/com/yingzao/addon/<id>/
    │   ├── <Id>AddonConfiguration.java                        # 装配入口(@ConditionalOnAddon)
    │   ├── <域>Service.java                                   # 业务逻辑(JdbcTemplate,SQL 就地)
    │   ├── <域>Controller.java                                # /api/<id>/** 端点
    │   └── <事件>Consumer.java                                # 总线 SPI(订阅别人的事件)
    └── resources/
        ├── addon.yml                                          # 插件清单(菜单/字典/api 闸/码段/mobile 工作台槽位)
        ├── META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
        ├── db/migration/<id>/V<段>__<名>.sql                  # Flyway 迁移(独立版本段)
        └── i18n/<id>.properties + <id>_en.properties          # 中英双语
```

装配三要素(缺一即不生效):①pom 入根 `pom.xml` `<modules>` 与 `yingzao-app/pom.xml` 依赖;②`application.yml` 的 `yingzao.addons.enabled` 追加 id;③AutoConfiguration.imports 指向配置类。i18n 迁移位置**零登记**——AddonConventionPostProcessor 按 addon.yml 自动发现(第 64 次)。

## 二、开工前必须知道的军规(违者返工,全文见 AGENTS.md)

1. **禁公司判断**——组织特性沉插件,内核与跨插件代码零 `if(company)`;
2. **禁依赖别的插件实现**——跨插件只准依赖 `yingzao-addons-api`(只读契约 + 领域事件);
3. **表前缀**——自有表 `{addonId}_`,扩展表 `{addonId}_{entity}_ext`;核心表永不因插件变更;
4. **错误码段**——在 addon.yml 声明独占段(如 target=370000),同码同消息,**先 grep 全仓码段台账防撞**(AGENTS「当前进度」尾部有全线段表);
5. **Flyway 独立版本段**——对齐码段(customer 200+/quotation 400+/…/target 1700+),MySQL 5.6 兼容(禁 DEFAULT 约束加列等 8.0 语法),**列名避开保留字**(year_month 教训,第 73 次);
6. **i18n 中英双语从第一行代码开始**——文案零硬编码,`MessageSource` 取文案;
7. **金额=厘(×1000 定点整数)**,数量千分位;算价服务端做,**禁信任前端金额**;
8. **状态迁移一律条件 UPDATE**(老读-判-写竞态灭绝);查重下沉 DB 唯一键(应用层查重仅作友好报错);
9. **主数据唯一写点**——客户/商品等主档只经其契约写,其他插件只读契约;
10. **gitignore 陷阱**:提交后 `git ls-files addons/addon-<id>/ | wc -l` 验源码真在册(target/ 规则会忽略同名源码目录,第 74 次事故)。

## 三、抄作业路径(按你要做什么查表)

| 你要做的 | 抄谁 | 关键姿势 |
|---|---|---|
| 端点 + 业务表 + RBAC 菜单闸 | addon-example LeaveService/Controller | Controller 零注解鉴权,addon.yml `api` 段声明 prefix→菜单;服务端 `requireAdmin` 类守卫用 RoleService |
| 接内核轻量审批(单级) | addon-example LeaveService | 业务单与 `yz_approval` **同事务**落库,带 biz 三元组;办结靠事件回写 |
| 多级审批串联 | addon-example LeaveApprovalConsumer | L1 通过事件里用内核 submit 派生 L2+改挂 approval_id;全部回写带 approval_id 守卫 |
| 订阅别人的领域事件 | LeaveApprovalConsumer / PaymentEventDemoConsumer | 实现 `YzEventConsumer` SPI,`eventTypes()` 声明,消费**幂等**(事件会重放);依赖会发事件的 Service 时构造参数 `@Lazy` 断环 |
| 发布领域事件 | 各 addon Service | `eventBus.publish(event, eventKey)` outbox 同事务;eventKey=业务幂等锚(如 `order:{id}:signed`) |
| 只读跨插件取数 | addons-api `DecorationApi`/`GoodsApi` 等 | 契约接口 + 提供方 `XxxApiImpl`;消费方零 SQL 直查他域表 |
| 定时/异步任务 | EchoPlanHandler(addon-example) | 实现 `YzPlanHandler`;周期任务=链式续期(member-expire-clear 参考:执行同事务挂下一轮) |
| 组织树节点数据(数据范围) | addon-target TargetService | 注入 `OrgScopeService.scopeOrgIds(node)`(自身+启用子树),逐组织聚合 |
| 收款/退款联动 | addon-sales SalesPaymentConsumer | 消费 PaymentCollected/Confirmed/Refunded,按 biz 三元组+typeCode 分流 |
| 建号/角色/组织管理 | 内核现成端点 | /api/users、/api/roles、/api/orgs(admin 守卫),不重复造 |
| Web 管理页 | web/src/views/** | 页面放 `views/<addonId>/<Page>.vue`,菜单 path 自动注册路由;api 函数入 `web/src/api/index.js`;视觉 token 用 `web/src/styles/yingzao.css` 变量(禁纯白残留) |
| 移动端页面 | app/src/pages | uni-app 一码三出;tabBar/pages.json 注册 |

## 五、example 的刻意边界(别抄错)

- addon-example 表与接口**刻意最小**(示范工程非业务插件):不要照它把业务 SQL 写在 Consumer 里(那是多级审批串联的特殊需要),常规业务逻辑放 Service;
- 它没有覆盖:多价格体系/套餐/组织树挂接/收付款联动——这些抄真实插件(表内插件名见 README 业务全景);
- 内核设施的完整设计动机见 docs/02 RFC §6(事件总线/审批/计划/槽位各节)。

## 六、冒烟(你的插件怎么进回归)

`docs/scripts/smoke/smoke_all.py` 是一键回归(1800+ 步):新增段落插**段尾**,用 `api_ok`/`api_err`/`step` 三件套断言,测试数据**自清理**(删行+回补),stamp 取当次时间保证跨轮唯一;跑法与账号见 `docs/scripts/smoke/README.md`。任何 ❌ 退出码非 0——「构建全绿才算完成」的最后一关。
