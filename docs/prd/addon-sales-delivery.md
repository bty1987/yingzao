## B2 原始诉求与老机制实证(先说清抄的是什么)

老系统两件套(2026-10-25 前后在产,厂商对账定制):

1. **品牌跳级权限**:`salesdeliverystatusright`(品牌×配送级)配 `checked`(免人工位,=0 该级系统自动通过)+ 递归连打——配送四级(1 配送 tran/2 审核 check/3 确认 confirm/4 完结 finish)按品牌裁剪,配置级自动推进、未配置级人工停驻;
2. **按配送批次分成**:`crate`(万分比)≠0 的级,推进到达即把该单×品牌的预结基准行(TYPE_BALANCE)**整行克隆**一条(type=TYPE_INIT、金额五字段 allowance/balance/vbalance/pbalance/difference ×crate、rate=crate 快照、**deliver_schedule=配送级作批次锚**),按 (sid,bid,type,onetype,status) 存在性幂等——「结算认领按配送进度分批」;
3. 两者**同表混配**(checked+crate 一张配置表)是老缺陷之一;另:crate 加总不校验(Σ≠10000 时分批合计漂移)、SerializationUtils.clone 整行拷贝(连 company 等归属字段一起抄)、按「操作级」切分而非业务里程碑。

**行业中性判断**:「配送驱动结算」本身是主材行业共性(分批供货分批结账/按到货验收节点付厂商),**方林嫌疑只在绑定其厂商对账返点玩法与操作级切分**。中性化 = 拆成两个正交概念,不抄实现。

## 业务闭环(一句话)

仓库/工程把一批主材送到节点并逐级确认,**厂商结算行按「里程碑达成」自动分批生成认领计划**(配送确认 40%、验收完结 60%——比例与节点由品牌配置),财务厂结/结算按批次对账,分批计划合计恒等于预结总额。

## 谁与场景

| 角色 | 场景 | 高频动作 |
|---|---|---|
| 仓库/工程 | 配送四级逐级推进 | 配送/审核/确认/完结(操作面 V1 已有,不变) |
| 销售主管 | 配品牌配送流程与分成计划 | 配模板:哪些级免人工、每级分成比例 |
| 财务 | 厂结/结算按批次认领 | 看分批计划行,按里程碑对账厂结 |
| 系统 | 里程碑达成 | 免人工级自动通过(track 留痕)+ 分批行幂等生成 |

## 核心模型(两表,一文件 V1104;预结行不动)

1. **`sales_delivery_flow`(品牌配送流程模板)**:uk(org,brand_id);`auto_tran/auto_check/auto_confirm` 三个 tinyint 免人工位(**finish 恒人工,不设位**——完结必须人确认,防自答);一行一品牌,未配置=四级全人工(V1 现行为不变)。与分成**正交**:只配流程不配分成合法;
2. **`sales_settlement_batch`(里程碑分批行)**:uk(org,settle_id,milestone);settle_id→sales_settlement.id(单×品牌行);milestone tinyint(1 配送/2 审核/3 确认/4 完结);rate 万分比快照;金额五列(balance/vbalance/pbalance/allowance/difference)按预结行×rate 逐列 HALF_UP;**末批=总额−已批合计补尾差**;status tinyint(0 计划/1 已认领)留 V2 扩展;
3. **触发点两处**:①配送明细推进到某级(含免人工自动通过)→ 该品牌有分成计划时按级生成分批行(幂等 uk,已存在跳过——修老 balance() 靠存在性幂等同构);②分成计划保存时重算该单该品牌未认领分批行(计划变更只影响未认领批次,已认领不回溯——诚实边界);
4. **Σ 守卫**(启用分成时):该品牌四级 rate 之和必须=10000(300201);只配部分级=其余级隐含 0,仍须 Σ=10000——修老加总漂移缺陷;
5. **免人工推进留痕**:自动通过级写 sales_delivery_item 对应级操作人=执行上下文账号+sales_track 记 `auto_` 前缀动作,人工逐级纪律不变(人不越级,系统按配置代打——V1「越级显式报错」对**人**保持)。

## 结算联动(三段式不动,分批行=认领计划)

- **预结行(sales_settlement)保持全额基准**,厂结/结算状态机零改动(0 预结→1 厂结→2 结算);
- 分批行是**计划与对账视图**:财务厂结时可见「该品牌结算总额按里程碑的拆分」;V1 分批行不驱动资金轴、不自动改 settlement 任何状态(诚实边界——资金动作仍全走既有三段式人工链);
- 厂结/结算完成回写分批行 status=1(已认领,按 settle_id 批量)——只做标记不参与守卫;
- 退货线不涉及(退货行负值,无分批;refund 场景分批行随结算驳回线自然不存在)。

## 老缺陷收敛表(重做即修复)

| 老缺陷 | 营造处置 |
|---|---|
| checked+crate 同表混配(流程裁剪与分成两义一张表) | 拆两表,正交配置 |
| crate 加总不校验,Σ≠10000 分批合计漂移 | Σ=10000 强守卫 300201+末批补尾差 |
| SerializationUtils.clone 整行拷贝(company 等归属字段连抄) | 分批行只落金额+rate+milestone 快照列,归属随 settle_id 引用 |
| 免人工级无留痕(系统代打与人工不可辨) | track `auto_` 前缀+操作人语义区分 |
| deliver_schedule 复用配送级 short,语义靠注释 | milestone 显式 tinyint 字典(deliveryMilestone) |
| 分成挂在「操作级」(检查/确认是操作不是业务里程碑) | V1 沿四级映射(配送/审核/确认/完结),命名中性化;业务里程碑(到店/验收)留 V2 随配送域演进 |
| 克隆行与源行间无关联列 | 分批行 settle_id 强关联+uk(settle_id,milestone) |

## 闭环校验

- 闭环起点:品牌配好流程模板+分成计划;
- 闭环终点:一批主材走完四级,分批行按里程碑齐了、Σ 分批=预结总额、财务按批次厂结对账;
- 异常路径:计划中途变更→未认领批次重算、已认领不回溯(留痕);免人工级推进失败→整单动作报错不静默;分批行生成幂等(重复推进零新增)。

## 非目标(本期不做)

- 业务里程碑模型(到店/验收独立于操作级)——随配送域 V3;
- 分批行驱动资金轴/自动厂结(资金动作恒人工);
- 供应商端自助对账门户/跨品牌汇总分成报表;
- 按出货口径分成(仅配送里程碑口径);
- 已认领批次回溯重算。

## 实现期核对清单(拍板后写码逐条销)

1. 老系统 checked 极性别照抄:营造语义=auto_* 三位显式命名(0/1),不复活「0=免人工」魔法值;
