# PRD - addon-member 会员营销(积分商城)

> L1 业务闭环 PRD。技术事实底座 = `docs/rules/member.md`(老系统五处四模块拼盘考证)。待业务方确认后写码。码段 **350000**,Flyway 迁移 **V1601+**(member 目录)。

## 业务闭环(一句话)

运营上线活动(倍数/有效期/适用域)→ 客户消费回款自动产生积分(分项账户)→ 客户在外部积分商城兑换礼品(回写本插件落兑换单,同事务扣积分+扣库存)→ 礼品核销(到店人工/签约自动)或撤销回补——**积分从产生到消耗全程留痕、额度实时可对账**。

## 用户与场景

| 用户 | 场景 |
|---|---|
| 运营/营销 | 建活动(适用域+倍数+有效期+默认活动)、上下架、停用;礼品目录维护(编号/价格/三开关/库存);礼品出入库/盘点;查积分台账与兑换单 |
| 财务 | 对账:积分分项账户(装修/主材/运营)与流水、兑换分摊映射;运营积分手工调整(外部商城对账入口) |
| 客户 | **不落本插件 UI**——在外部积分商城小程序兑换;员工代查积分(客户详情侧栏) |
| 外部积分商城系统 | 服务账号经角色授权调同步 API:商品目录 upsert / 兑换单落单 / 撤销 / 状态回传 |

## 核心流程(状态机文字版)

### 1. 活动主档 activity
```
status: 0 有效 ⇄ 1 失效(可逆)
字段:type(1 装修/2 主材/3 销售,适用域)+ multiple(千分位,1000=1 倍,待业务确认)
     + validays(收款后有效天数,必填 >0)+ startTime/endTime(必填,查询真生效——修老"时间窗形同虚设")
     + isDefault(每 type+org 唯一,新默认顶旧默认,旧默认自动让位;默认活动可停用但需二次确认——修老 160047 硬禁)
规则:客户单笔收款记分时按"单绑定活动优先,否则该 org 该 type 默认活动"取倍数(修老 take-first 与双路 aid 传递)
```

### 2. 积分账户(事件驱动,废除实时 SQL 聚合)
```
分项账户:org+customerId 维度,分项 pointType(1 装修/2 主材/3 运营)各持 balance
记分:消费收付款确认事件(PaymentConfirmed/Refunded,sales/payment 域既有总线事件)→
     按 款项金额(厘)×multiple(÷1000) 记积分(整数),写流水;validays 语义=该笔积分自收款日起 validays 天内可兑
     (核销时校验,过期只拦新兑换不清零——沿老系统,V1 无清零任务,流水保留将来清零钩子)
流水 record:只追加,type 增/扣/撤销反向;分摊映射:积分↔款项行(对账用)
运营积分:手工调整端点,必填原因,留痕(修老 operatePoint 被外部同步无条件覆盖)
并发:余额扣减用条件 UPDATE(WHERE balance>=:x)原子扣(修老 read-modify-write 互踩)
```

### 3. 礼品目录与库存 gift/gift_record
```
礼品:no 编号(全局唯一,外部商城商品一等公民)/name/unitPrice(厘)/三开关
     isPrefor(算业绩)/isStock(算库存)/isPayment(计金额),语义 0=算 1=不算(原样保留)
     + status 0 可用 1 禁用 + org(去老"总部仓硬编码",按 org 建库存)
库存流水 gift_record:只追加,type 入库/出库/盘盈/盘亏 × 业务动作 subtype;
扣减:条件 UPDATE 原子扣(WHERE num>=:x),不足 350003(修老 9 处 check-then-act 竞态)
目录同步:外部商城 upsert by no(命中更新/否则新建,回显 created,并发 DB 兜底重查——沿 supplier ext_no 幂等模式)
采购流(AwardPurchase)V2(待业务确认 §13-3)
```

### 4. 兑换 exchange(单+明细)
```
状态机(单):0 已受理 → 1 已核销 / 2 已撤销 / 3 已发货(V2,对接物流时启用)
状态机(明细):0 受理 → 1 已核销 / 2 已撤销;核销一次性(唯一约束,重复 350011)
落单(外部商城同步,幂等):以商城单号 exchangeNo 幂等 upsert——命中重复回显不重扣;
     校验:积分余额足额(分项逐项校验 350006)/礼品可用+库存足额(isStock=0 才扣)/每单每线上礼品限 1 件
     (DB 唯一约束+服务层精确计数,修老 off-by-one)/活动有效期
     → 同事务:扣积分(写流水+分摊)/扣库存(写流水)/落明细
撤销:仅明细 0 可撤(350012);整单撤销校验全部明细可撤;
     反向回补积分+库存,写反向流水,原单留痕不删
核销:consume(exchangeId) → 明细→1,校验积分对应批次过期(validays)/每单每礼品一次;
     签约自动核销:监听装修单签约事件(decoration 域既有),按配置开关执行,content 取配置(修老硬编码字面量)
```

## 闭环校验(异常路径)

- 积分不足 → 350006,兑换拒绝;礼品禁用/不存在 → 350004/350002;库存不足 → 350003;
- 兑换单号重复 → 幂等回显(非错误);明细超限 → 350008;已核销再核销 → 350011;不可撤销状态 → 350012;
- 过期积分:不影响账户余额展示,只拦核销(350009),明细行自带过期时间可查;
- 外部商城重复推送/乱序:全部幂等(upsert+状态机拒绝乱态迁移);
- 撤销已核销 → 拒绝(修老 cancelMemberOrder 不校验状态作废已核销商品的缺陷)。

## 验收标准

1. 建活动(装修域/千分位倍率/30 天有效期/设默认)→ 装修单收款确认事件到达 → 分项账户增加 款项×倍率÷1000 积分,流水含分摊款项行;28 天后核销兑换通过、第 31 天兑换被 350009 拦截(有效期语义);
2. 未绑活动的单收款 → 按 org+type 默认活动倍数记分;两个 org 各设默认互不影响;
3. 商城同步落单:同 exchangeNo 推两遍 → 第二遍幂等回显,积分只扣一次;并发推两单、余额只够一单 → 恰好一单成功一单 350006(条件 UPDATE 实证);
4. 兑换 isStock 礼品:并发两单各购库存仅剩 1 件的礼品 → 一单一 350003(原子扣实证);isStock=1 礼品不扣库存;
5. 每单每线上礼品第 2 件 → 350008(DB 约束兜底,绕过 API 直插也被约束拦);
6. 撤销未核销明细 → 积分库存对称回补+反向流水;撤销已核销 → 350012;
7. 礼品目录 upsert:新建/更新/并发同 no 三态各自回显正确(沿 supplier 冒烟范式);
8. 停用活动不再记分(存量已记积分不受影响);切换默认活动旧默认自动让位、事件留痕;
9. 错误码 350001-3500xx 同码同消息,i18n 中英双语;RBAC:member 菜单+api 段声明,商城同步端点走服务账号角色,smoke_enforce 零未声明;
10. mvn clean package 全绿;冒烟新增 member 段全绿,smoke_all 总量全绿一次通过。
