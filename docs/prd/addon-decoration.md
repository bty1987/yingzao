## 业务闭环(一句话)

设计师/销售把已转化的客源登记为**装修单**(客户×楼盘唯一),经 定金→预签→签约→(施工期)→决算 的主线推进,四条状态线(合同/工程/设计/确认)各自留痕,最终以"决算归档或废单/终止"终态收口,供报价/施工/款项/主材各域挂载;关键节点(分配/签约/状态变更)经领域事件触发通知中心触达责任人。

## 用户与场景

| 角色 | 场景 | 高频动作 |
|---|---|---|
| 设计师 | 客源转化后建单 | 登记装修单(客户+楼盘+类型)、跟进设计线确认 |
| 销售顾问 | 归属与业绩 | 查看自己归属的单、转归属/合尺 |
| 设计总监/经理 | 审核与流转 | 废单、发起终止(审批后生效)、改派 |
| 客户 | 微信确认 | 确认设计方案/施工方案(确认线 0→1→2) |
| 店长/总经理 | 全景 | 按视角(权限)查看全量单、看里程碑 |

## 核心流程(状态机文字版)

1. **建单**:登记(客户+楼盘+半包/包干/整装)→ 合同线 0 初始;单号自动生成;归属(设计师+销售)落库;发布 `DecorationCreatedEvent` → 通知。
2. **定金/预签**:收定金 → 1;预签门槛=预单锁定+活动锁定 → 2。
3. **签约**:门槛=已收合同款+无未审审批+报价锁定 → 3;联动:报价锁定、设计线 0→1、账户状态、`DecorationSignedEvent`。
4. **设计确认线**:客户微信确认合同方案(sourceStatus 1,微改 11/大改 21)→ 放线确认(2);量房放线成功 → 工程线 0→1 开工。
5. **重签**(可选):仅签约后、无增减项 → 4(留 recontractTime,不覆盖首签时间)。
6. **废单**:仅未签约前(排除已签/完工/终止/重签)→ 5。
7. **终止**:先审批进过渡态(32/33)→ 执行终止 → 6;联动退未付款项计划、报价留痕生效、归属失效。
8. **决算**:门槛=六项前置检查(组织级配置开关与阈值)→ 7 → 完工 8。
9. 全程操作轨迹留痕;每步状态变更发领域事件,通知中心给相关人发站内信。

## 闭环校验

- 闭环起点:客源转化(LeadConvertedEvent 后)或直接登记 → 合同线 0。
- 闭环终点(终态):8 完工(正常收口)/ 5 废单、6 终止(异常收口);其余状态均应可到达终态之一。
- 异常路径:查重(同客户×同楼盘存在在途单即拒 250001);非法流转(迁移表白名单外拒 250002);前置缺失(未收合同款签约 250003、报价未锁定 250004、审批未清 250005)均拒绝并双语提示;终止必须先经审批过渡态,不可直接终止签约单。

## 非目标(本期不做)

- **三口径表算法**(半包配比/整装满减/包干增项三分支)→ V2,与 quotation 成本线联动后一起做;
- **合同电子签**(厂商路由/签署/归档)→ 独立 provider 插件,待用户选定厂商;
- **活动/券/核销**域 → 独立营销 addon(待划界确认,rules §16.10);
- **决算账户与余额** → 随款项域(addon-payment)一并设计;
- **审批量表(AuditScale)冲账/回冲** → 随自研轻量工作流排期;
- 审批过渡态(20/30/32/33)的具体审批流引擎——沿用已拍板的"轻量自研状态机",不用 Flowable。

## 验收标准

- [ ] 建单:同客户×同楼盘在途单查重生效;单号按"前缀+yyMMdd+序号"生成且唯一;创建后主档+1:1信息+归属+轨迹同事务落库;`DecorationCreatedEvent` 发布且责任人收到站内通知。
- [ ] 主线推进:0→1→2→3→7→8 全链可走通;每步门槛校验(签约必须已收合同款+报价锁定)生效。
- [ ] 异常收口:废单前置排除法生效;终止必须先审批过渡态;决算前置检查按组织配置执行。
- [ ] 确认线:0→1→2 不可跳步不可倒退;微改/大改变体按确认口径落库。
- [ ] 四条状态线独立推进互不覆盖;所有非法迁移返回 250002 且中英双语。
- [ ] i18n 双语完整;错误码全部落在 250000 段;迁移 V500+ 位于 addon 独立 location。
- [ ] 插件零反向依赖:事件入 `yingzao-addons-api`;通知消费走内核 NotificationService(零业务知识)。
