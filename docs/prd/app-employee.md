## 业务闭环(一句话)

**员工**在手机上完成「客源登记 → 跟进 → 报价/合同查阅 → 施工操作与留痕 → 审批流转 → 通知触达」的日常业务闭环;移动端**零独立业务表**——全部经 addons-api 契约消费各 addon 既有能力,数据终态与 Web 端完全同源。

## 用户与场景

| 角色 | 场景 | 高频动作 |
|---|---|---|
| 监理/质检/工程经理 | 工地现场 | 我的工地列表、节点开工/完工、施工日记拍照、图纸查阅 |
| 业务员/设计师 | 外出带客 | 客源登记/跟进、定金登记、查销售单与收款流水 |
| 全员 | 审批与通知 | 待审列表、同意/驳回、发起审批、通知跳业务单 |
| 全员 | 工作台 | 宫格进入有权限的功能(无权限的格子不出现) |

## 移动端接口契约原则(军规级,从方林教训反推)

1. **角色差异不造多个接口**——一律一个接口 + 数据范围(docs/03/08 基座),前端不感知角色;
2. **金额不换算**——后端 DECIMAL 直传,移动端零换算层(否决方林 tranargs ×1000);
3. **令牌走 header**——Bearer(app 已如此),免登链路换发同一 token;
4. **分页统一** `page/rows`,列表 onReachBottom 累加;
5. **枚举一律接口取**——禁止 `Public/json/*.json` 式前端静态枚举(双源风险,字典单源红线);
6. **操作接口幂等**——开工/完工/发货类动作后端状态前置校验,前端不做闸门以外判断。

## 闭环校验

- 闭环起点:员工登录(账密;C4 后宿主免登)→ 工作台宫格;
- 闭环终点:业务动作落各 addon 既有表,Web 端立即可见同一数据(同源校验);
- 异常路径:接口失败兜底提示 + 本地草稿(客源登记/施工日记);令牌过期统一 401 → 重登。

## 非目标(本期不做)

- 原生宿主小程序(钉钉/微信原生)——坚持 uni-app 一码多端(方林 Applet 实验已证伪);
- 工人工费**录入**(addon-salary 商业插件,P2 只读查询);
- 改手机号/钉钉用户重建/招聘表单等低频管理动作(留 Web 管理端);
- 活动票/会销/外呼(docs/01 已判删除);
- 任何金额 ×1000 前端换算、宿主 secret 前端硬编码(军规禁止)。
