# PRD - addon-inventory 库存

> 状态:草稿(2026-10-11,待业务确认)
> 老系统参考:inventory 模块(实现者回溯指针见文末;实现口径见 `docs/rules/inventory.md`,二者同日产出)

## 业务闭环(一句话)

仓管/门店对商品做**出入库记账**(进货/出货为手工入口,采购入库/领料/调拨/盘盈亏/套拆合为系统派生),库存实时账随单据即时增减;辅料领用受工程额度约束、外辅采购协同厂商完成送收结算,最终数据终态落在「库存事件流水 + 商品×色×规×仓库实时库存」。

## 用户与场景

| 角色 | 场景 | 高频动作 |
|---|---|---|
| 仓管 | 日常出入库 | 建进货/出货单(挂销售单)、确认、打印 |
| 仓管 | 库存查询 | 按授权仓库查实时库存、查单据流水 |
| 项目经理/施工 | 辅料领用 | 发起领料单(受工程额度双闸)→ 出库 → 退库 |
| 外辅协调员 | 向厂商定材送料 | 登记外辅单 → 分配厂商 → 送货/到货 → 结算/作废 |
| 采购 | 采购入库 | 建采购单(挂销售单)→ 分批入库 → 采购单自动部分/全部入库 |
| 厂商(外部账号) | 外辅协同视角 | 查看被分配的送货单、录送货回执 |
| 财务/审计 | 流水追溯 | 按类型/日期/仓库查出入库流水 |

## 核心流程(状态机文字版)

1. **出入库单(核心)**:建单(进货/出货,建单事务内即时增减库存事件)→ 初始(可改行/删行,改删同步回冲库存)→ 确认(账面锁定);冲销=反向类型新单(进退/出返),无作废;其余 10 类(采购入库/领料/退库/调拨/套合/套拆/盘盈/盘亏)由对应业务动作派生,落单即确认;
2. **库存事件(架构分层,营造新增)**:任何库存增减=一条库存事件(类型/商品×色×规/仓库/数量/源单),实时库存表按事件原子增减(`UPDATE ... WHERE num>=:num` 防超扣,唯一真守卫);销售侧出货余量/采购占用/工程额度由 **addon-sales/addon-construction 订阅事件回写自己的账**,inventory 零直写他域;
3. **领料单**:发起(工程额度总额+per-gid 双闸校验)→ 预出 → 出库(派生领料出库事件)→ 到货;撤销/拒绝(仅初始态,回退额度);售后类型跳过工程联动;可选审核环节走内核轻量审批;
4. **外辅采购单**:登记(装修单未验收)→ 分配厂商(通知)→ 送货 → 到货 → 结算(V1 单据内金额自闭环,线下钱货)→ 完成;作废仅到货前可操作,单据保留不可再操作;反结算 4→3;
5. **采购单**:建单(挂销售单)→ 分批入库(每次入库派生采购入库事件,采购项余量核销)→ 自动判定部分/全部入库(终态);取消/删项**释放占用配额**(修正老系统 punum 永不释放缺陷);采购结算直接复用 addon-payment 统一结算模型(老 purchasebalance 生产 0 行,不迁不仿)。

## 闭环校验

- 闭环起点:第一张进货单(商品建档后的库存行诞生);
- 闭环终点(终态):出货单被出返反向冲销/采购单全部入库/外辅单完成或作废/领料单出库后到货或退回;
- 异常路径/回滚:冲销走反向单不留负数单;外辅/领料可作废(到货/出库前);数量守卫(负库存禁扣/源单余量足量)全程原子化;所有金额/数量服务端重算,不信任前端(修正老 total=0 与客户端 total 绕闸两类事故)。

## 非目标(本期不做)

- 出库单模板(manifesttemplate,生产 0 行,从未投产);
- 月结快照表(storehousestock,写点死表)——报表按事件流水实时聚合;
- 盘点 checklist 孤表不迁;若业务要盘点,以盘盈/盘亏事件单闭环另立小需求;
- 采购结算手工台账(purchasebalance,生产 0 行)——统一走 addon-payment;

- 厂商即用户模型——厂商身份归 addon-supplier,外辅协同走其端点;
- 多仓库调拨的复杂审批编排——单级审批用内核轻量审批即可(V1);
- 移动端外辅厂商视角(uni-app)V1 先 Web,厂商协同端随 addon-supplier 一起排期。

## 验收标准

- [ ] 进货/出货建单即产生库存事件,实时库存随事件原子增减,并发同商品出库不超扣(压测两并发);
- [ ] 出货挂销售单时,addon-sales 出货余量经事件回写,inventory 代码零出现 sales 表;
- [ ] 出返/进退反向单回冲库存与销售侧计数,原单余量守卫生效;
- [ ] 领料单双闸:工程额度不足与 per-gid 超量分别拒绝(错误码独立双语);撤销回退额度;
- [ ] 外辅单 0→1→2→3→4→5 全流转+作废(仅 0/1/2)+反结算(4→3),作废后所有写点拒绝;
- [ ] 采购单分批入库自动判定部分/全部;删项/取消释放配额(与老系统 punum 泄漏形成对照);
- [ ] 零明细单/负数数量/超大 int 全部服务端拒绝(修老恒假守卫与溢出嫌疑);
- [ ] 错误码 310000 段双语,零跨段借用;字典走 dicts.yml,0=肯定反直觉语义全部翻转;
- [ ] 组织隔离:库存/仓库/单据全链 org_id 过滤(修老多租户半成品);
- [ ] Web 页面:出入库工作台/库存查询/领料/外辅/采购五页,菜单由 addon.yml 下发零硬编码。

## 端覆盖

- Web 后台:出入库工作台(建单/确认/冲销)、库存查询(按授权仓库)、领料管理、外辅采购(协调员视角)、采购入库;外辅单详情挂 addon-supplier 厂商回执槽位(slot);
- 移动端(uni-app):领料发起/外辅送货到货拍照回执(inventorydrawing 语义归通用附件);
- 企微/钉钉:外辅分配厂商时通知协调员/监理(事件→插件自调内核通知,沿 addon-customer LeadAssignedNotifier 先例)。
