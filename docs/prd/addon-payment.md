# PRD - addon-payment 款项

> 状态:**草稿(待业务方确认,2026-10-11)**。确认前不写业务代码(纪律同 customer/quotation/decoration/construction)。
> 老系统参考:`com.fanglin.payment`(185 文件/19 ServiceImpl 约 9300 行);实现口径回溯指针见文末,完整提取见 `docs/rules/payment.md`。
> 码段 **270000**,Flyway 迁移段 **800+**(顺延 basedata 260000/700+,最终以实施顺位为准)。

## 业务闭环(一句话)

组织在任意业务线产生应收时,由 addon-payment 统一落**款项单**(类型字典化:类型/顺序/比例模板),出纳经**统一收据**(双人留痕+多渠道合计平衡)完成收款、财务**确认**后终态;预付款按**组织自定义科目**的余额台账收/支/划扣(原子扣减);每笔收/退/确认发领域事件,各业务插件(装修单/主材/销售/增减项)自监听回写自身状态——数据终态落在款项单 2 已确认、收据已确认、预付款余额=Σ流水可对账。

## 用户与场景

| 角色 | 场景 | 高频动作 |
|---|---|---|
| 出纳/财务 | 收款执行 | 按款线收款(多渠道合计=应收)、开收据、批量收款(V2) |
| 财务主管 | 复核与资金安全 | 确认款项、退款审批(走内核审批中心)、预付款收付 |
| 销售/设计师 | 业务侧跟单 | 查看自己单据的款线进度、催收提醒 |
| 客户 | 线上参与(V2) | 微信收据查看、线上确认 |
| 组织管理员 | 配置 | 款项类型字典(顺序/比例模板/限额)、预付款科目字典 |

## 核心流程(状态机文字版)

1. **款项单生成**:业务插件经 addons-api 契约调用 payment API 创建 Bill(type=款项类型字典行:携带 sort 顺序/比例模板/限额配置)。签约拆分款线 = 按比例模板多项拆分(取整规则与尾差兜底口径见 §13.1 待拍板)。存量已收款 → 拒绝重建(修老系统硬删重建)。
2. **收款 0→1**:守卫三件套(款项存在/状态可操作/Σ渠道==应收),**顺序门控**(sort>1 时前置款项未收 → 拒);收据落库(收款人+时间戳双人留痕的第一半),先验后写(收据与校验同事务,**禁先写后验**)。
3. **确认 1→2(终态)**:财务确认,补 confirmer+确认时间(留痕第二半)。"收款即确认"是否服务端一步化见 §13.2 待拍板,V1 默认 collect/confirm 两步保留财务复核职能。
4. **退款**:统一走**内核轻量审批**(废弃老系统直接退/审批退/设计费跳审批三轨并存):提交审批 → 通过后新建退款款项单+原款项置终态(带状态快照,修"驳回顶态"缺陷);已确认款必审批,初始态小额直退与否见 §13.3。
5. **预付款**:组织自定义科目字典(默认预置 合同/工程/主材 三科目,替代老系统"正林列级硬编码");余额表+流水表分离,**所有余额变动走原子 SQL**(balance>=delta 条件更新,复活老 DAO 死代码);金额入参强制 >0(修负数反转余额);业务插件划扣经 payment API 发起并落流水。
6. **事件回程**:PaymentCollectedEvent / PaymentConfirmedEvent / PaymentRefundedEvent / AdvancePaymentChangedEvent(addons-api 契约)→ 业务插件自监听回写:装修单首收升定金、增减项置已付+生成定额、销售/主材单作废联动、厂商结算推进等**全部归各业务插件**,payment 零业务知识。

## 闭环校验

- 闭环起点:业务插件产生应收(Bill 创建);终点:Bill 2 已确认 / 退款单终态;预付款任意时点 余额==Σ流水。
- 异常路径(全部双语 i18n,270000 段):款项不存在 / 状态不可操作 / 渠道合计≠应收 / 前置款项未收 / 余额不足 / 负数与零金额拒绝 / 退款审批中重复操作 / 科目不存在;并发收款以状态条件 UPDATE 兜底(两次只成功一次)。
- 口径红线:**金额单一制式**(分 or 厘见 §13.1,全库统一禁混用)、比例单一制式(‰)、**禁事务内网络调用**(渠道回调异步化,渠道插件 V2)、**禁静默跳过/静默 return**(失败必须可见)。

## 非目标(本期不做)

- **渠道适配**(微信/支付宝/POS/swiftpass)= PaymentChannelProvider 扩展点(addons-api)+ 支付插件族,V2;V1 收款渠道行仅为"方式记录"(现金/银行/扫码结果补录);
- **钱包族不迁移**(半成品:绑卡状态机断裂/卡明文/空桩);代付款/活动款/外销款/对账 V3 随对应插件;
- **客户微信确认链**(isAffirm 验证码+手机匹配)V2(涉短信/微信凭证);
- **批量收款 N:1 收据挂接、分次支付聚合** V2;
- **服务款拆分/封顶重做** V2(老实现清零退款是高危缺陷,重做后并入);
- PaymentFunction 功能字典 → 已收编 RBAC capability(rules §9),本 addon 不建 right 族表;
- 比例双闸(销售比例逼单)不做——公司玩法,归销售提成插件(§13 待拍板);
- 电子签(款项合同)随电子签插件。

## 验收标准

- [ ] 三件套主链:Bill 创建(事件/API 两入口)→ 收款 → 确认全链走通;守卫三件套+顺序门控生效,错误码全落 270000 段双语;
- [ ] 类型字典:款项类型(含顺序/比例模板)组织级可配,新建类型零代码;**禁中文名字符串分支**(老 paymentType contains("退款") 类协议灭绝);
- [ ] 预付款:科目字典化;两并发扣减不超支(原子 SQL);负数/零金额拒绝;余额==Σ流水对账脚本通过;划扣流水含业务溯源单号;
- [ ] 退款:全走内核审批;通过前原款项可守卫、通过后原款项终态+退款单生成;驳回不改原款项状态(带快照);
- [ ] 事件:收/确认/退/预付款变动四事件发布,示范插件消费回写成功(零反向依赖,只依赖 addons-api);
- [ ] 迁移 V800+ 在 addon 独立 location,MySQL 8 基线;零公司判断、零硬编码文案。

## 端覆盖

- Web 后台:款项单工作台(按业务线/状态过滤)、收款与开收据、预付款台账(按科目)、类型与科目字典管理;退款审批复用内核审批中心页;
- 移动端(uni-app):收款记录查询、预付款余额查询、审批待办(内核已有);
- 企微/钉钉:收款到账通知、退款审批待办触达(内核通知中心+审批事件)。
