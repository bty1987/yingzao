# PRD - webmp-portal 客户端门户(对外)

> 状态:草稿(2026-10-28,待业务拍板)
> 需求来源:[docs/13-微信端产品矩阵归纳PRD.md](../13-微信端产品矩阵归纳PRD.md) §九(方林微信侧二十年 C 端实证,经 01 判断法过堂)
> 现状基线:web-mp 已有 6 页(案例/进度列表/进度时间轴/积分/我的/验证码登录,tabBar 四项),H5 已上线
> 工程形态:uni-app 一码双出(H5 + 微信小程序);后端聚合口 = addon-portal,数据经 addons-api 契约取自各 addon

## 业务闭环(一句话)

**客户/访客**在微信里完成「看案例留资 → 签约后绑定订单围观工地 → 查资金流水 → 待确认事项线上确认 → 会员积分复购」的 C 端全旅程;数据终态落各 addon 既有表,portal 只做**聚合投影**,零独立业务表(匿名面组织上下文 = yingzao.portal.org-id)。

## 用户与场景

| 角色 | 场景 | 高频动作 |
|---|---|---|
| 访客(匿名) | 获客触点 | 看案例、分享、留资转进线(随 addon-market V2 名片族) |
| 业主(履约中) | 围观工地 | 看进度时间轴、工地相册/板拍、查收款流水 |
| 业主(关键节点) | 线上签字 | 待确认列表 → 详情 → 确认/驳回 |
| 业主(售后/复购) | 会员 | 查积分、报修(随 addon-service)、老带新分享 |

## 闭环校验

- 闭环起点:访客匿名逛案例(免登白名单)或业主验证码登录;
- 闭环终点:确认类动作回写各 addon 状态机(与 Web 端同一终态);资金流水与 addon-payment 同口径(同一 service);
- 异常路径:接口失败兜底默认图/空态;未绑订单看不了进度(登录墙);手机号不匹配订单拒确认(实名闸);提审合规——支付类动作展示转客服咨询(双版本翻转机制)。

## 非目标(本期不做)

- 原生微信业主小程序(web-mp 一码双出 mp-weixin 即可);
- 员工微信小程序——员工移动办公收口 `app/`(见 [app-employee PRD](app-employee.md),docs/13 §八已判"第三条端线维护不起");
- 商城/会销票务/群享/抽奖(docs/01 删除项);
- 支付渠道真实对接(C2 凭证到位后按 PaymentChannelProvider 独立立项);
- 修复方林历史风险(测试号 secret 明文、硬编码鉴权码、废弃 API)——老系统自己的债。

## 工程军规(从方林实证反推)

1. C 端只读投影独立端点(`c-customer` 段),**不暴露管理端点给 C 端**;
2. 匿名可逛 + 登录墙分层:案例匿名,进度/资金/确认必须登录且本人;
3. PII 零明文:手机号等经 portal 投影一律脱敏(老系统 C 端硬编码鉴权码是反面教材);
4. 首页永不白屏:所有匿名接口失败有兜底图与空态;
5. 提审合规机制照 docs/13 §九工程注意(双版本翻转、支付动作转客服)。
