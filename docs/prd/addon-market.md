## 业务闭环(一句话)

营销策划创建**活动×渠道**并生成**投放源**(渠道码/二维码/UTM)投放到公域,访客经落地页留资成**进线**(幂等去重+手机加密+动态表单字段),系统自动**承接**为 addon-customer 的客源/机会并落**归因事件流水**,形成"投放→进线→客源→机会(→成交)"可按活动/渠道统计的获客漏斗;案例库为官网提供内容获客物(城市/风格/户型/面积筛选+报名留资直接进漏斗)——数据终态落在进线 1 success、归因流水 insert-only、客源/机会归 addon-customer。

## 用户与场景

| 角色 | 场景 | 高频动作 |
|---|---|---|
| 营销策划 | 投放管理 | 建活动/渠道、生成投放源(码/二维码/UTM)、发布与停用 |
| 网销/客服 | 进线跟进 | 查进线列表(含失败原因)、重试承接、人工补承接 |
| 市场经理 | 效果复盘 | 按活动/渠道看漏斗(进线→客源→机会转化数)、预算记录 |
| 官网访客 | 内容获客 | 浏览案例(城市/风格/户型/面积筛选)、报名留资 |
| 销售顾问 | 名片获客(V2) | 制作电子名片、收留资通知 |

## 核心流程(状态机文字版)

1. **投放物**:活动(0 草稿→2 发布→3 停用,5 归档终态;停用/发布后不可改)×渠道(启用/停用,**带恢复接口**——修老系统无恢复)→ 投放源(code 唯一约束+URL+二维码+UTM 三件套,归属校验:活动与渠道同组织且与来源一致)。
2. **进线登记**:落地页/渠道机器人提交 → 三重校验(活动/渠道/来源存在+归属一致)→ 幂等键(组织+活动+来源+手机 hash,phone 缺失走显式"匿名进线"策略,禁掺 UUID 退化)→ **DB 唯一约束兜底**+命中幂等返回全量(含动态字段与承接结果)→ 手机密文落库+hash 查重 → 0 待承接。
3. **进线状态机(闭环化)**:0 待承接 → 1 承接成功(清错误信息)/ 2 承接失败(错误信息留痕);失败与待承接均可**重试**(重试须权限校验+留操作日志——修老系统无权限无日志);新增 4 忽略(人工显式关闭,带操作人——修死状态);**承接结果对提交方可见**(废"登记永远成功"式静默)。
4. **承接(与 addon-customer 衔接,架构核心)**:进线受理发 `InboundAcceptedEvent`(addons-api 契约,载荷=承接参数:客源/机会两档),addon-customer 监听走自己的建档→房产→客源→派发链(含撞单策略,策略可配置),完成后经 market 回写契约回填 csid/ccid 并落归因事件——**废跨插件 REQUIRES_NEW 直调**(孤儿事务预防:回写前 customer 侧幂等,重试安全)。
5. **归因流水**:insert-only 四级事件(0 提交/1 建客源/2 建机会/3 成交【是否 V1 见待确认】),进线行冗余三键供统计;漏斗查询=按活动/渠道分组计数(有效进线=承接成功口径)。
6. **案例库**:城市字典(拼音自动生成+默认运营城市配置化,去硬编码)→ 案例(城市/楼盘/风格/户型/面积/工期,上下架布尔开关)→ 图片(级联删除);官网查询=(城市,上架,类型)分页可配条数;**报名=一种进线入口**(复用进线链路+归因,手机加密——废独立明文 ecustomer 表)。

## 闭环校验

- 闭环起点:投放源产出/进线登记;终点:进线 1 success(承接回写完成)+归因流水落库;案例报名同样进漏斗。
- 异常路径(280000 段双语):活动/渠道/来源不存在或归属不一致 / 幂等命中(回全量非报错,业务码提示)/ 承接失败(错误信息可见+可重试)/ 撞单(策略在 customer 侧可配置)/ 无效验证码(报名,常量时间比较)/ 匿名进线策略确认。
- 红线:**手机号密文存储+hash 查重全域强制**(名片/报名/进线统一,消灭明文孤岛);网络外呼(通知/ISV)一律移出事务;禁静默失败(所有失败可见可重试);禁跨插件表直写(事件+契约)。

## 验收标准

- [ ] 投放链:活动/渠道/投放源 CRUD+状态机闭环(含恢复);source code 组织内唯一(DB 约束);归属一致性校验生效;
- [ ] 进线:幂等(同键并发仅一条,DB 唯一约束实证)+手机密文+动态字段;状态机含忽略态与重试权限校验;失败原因对提交方可见;
- [ ] 承接:InboundAcceptedEvent 发布→addon-customer 建档链走通→回写契约回填+归因落库;customer 侧不可用时进线滞留待承接可重试(无孤儿数据);
- [ ] 归因:insert-only 流水;按活动/渠道漏斗统计(进线/客源/机会三级)与老口径对得上;
- [ ] 案例库:五件套 CRUD+上下架+图片级联删除;报名复用进线链路(加密+归因);默认运营城市配置化;
- [ ] i18n 双语完整;错误码全落 280000 段;迁移 V1000+ 在 addon 独立 location;零公司判断、零硬编码文案、零跨模块表直写。

## 端覆盖

- Web 后台:投放管理(活动/渠道/来源+二维码下载)、进线工作台(状态/失败原因/重试)、漏斗看板(按活动/渠道)、案例库管理(城市/案例/图片/报名列表);
- 移动端(uni-app):进线提醒与跟进、销售个人名片(V2);
- 企微/钉钉:进线承接结果通知、报名线索待跟进(通知中心);
- 官网/C 端:案例展示页+报名表单(经开放 API,独立端点鉴权走 RBAC v2 匿名段,待设计对齐)。
