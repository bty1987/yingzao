# 08 - 组织树与数据范围设计(组织模型裁决与演进路径)

> **本文是什么**:组织模型的架构裁决记录与设计稿。裁决由业务方于 2026-10-21 拍板(回应 docs/07 fl-yy 反哺评估中「fl-yy 三层组织形态 vs yingzao 单层组织军规」的张力问题),本文将其落为可实施的模型设计与演进路径。
> **裁决一句话**:组织是**一棵自引用树**——`公司 → 分区 → 部门 →(子部门…)`,层级是树上的深度标签而非独立实体;**不做「集团 / 分公司」两类公司实体的复杂模型**。多公司时树根即集团视角,单公司时树根即公司——同一模型,不同企业层级数不同而已。

---

## 一、裁决原文与解读

> 「层级为公司-分区-部门,不需要集团分公司的模式;或者可以理解为集团-公司 / 公司-分区 / 分区-部门 / 部门-部门——就是不同的组织架构而已。」

解读三则:

1. **一棵树,多种深度**:不同装企的管理层级数不同(小公司公司→部门两级就够,大连锁公司→分区→部门→班组四级),模型必须兼容任意深度,不硬编码「必须几层」;
2. **层级标签是视角不是实体**:「集团」「公司」「分区」「部门」是同一类节点(organization)上的类型标签;叫「集团」的节点与叫「公司」的节点在模型上无差别;
3. **fl-yy 的「战区/分部」落到此树 = 「分区」层**:docs/07 fl-yy 反哺中的 BattleBoardDivisionTargetPlan(组织×战区×目标月)等模型,其「战区」不再是需要专门建制的实体,而是树上某个分区节点的标签。

## 二、模型设计

### 2.1 organization 树(V108,内核 100-199 段)

```sql
alter table organization add column parent_id   bigint null  comment '父节点(NULL=根)';
alter table organization add column level_type  varchar(16) not null default 'department'
    comment '层级标签:company/region/department(展示与筛选用,不参与权限判定)';
alter table organization add column org_path    varchar(512) not null default '/'
    comment '物化路径:/1/5/12/(含自身 id,子树查询与校验用)';
alter table organization add key idx_org_parent (parent_id);
alter table organization add key idx_org_path (org_path(191));
```

- **存量兼容**:现存单层 org(如 dev 的 org 1)自动成为根节点(parent_id=NULL,org_path='/1/'),全部既有数据(org_id 外键)零迁移;
- **org_path 物化路径**:子树查询 = `where org_path like '/1/5/%'`(O(索引) 拿到整棵子树,免递归);节点移动 = 子树 path 前缀重写(低频管理动作,事务内一条 UPDATE);
- **level_type 只是标签**:数据范围判定不依赖它(看路径),前端展示/筛选用它;新建节点自由选标签,校验只保证「company 不得挂在非根下」一条软规则(V1 可不校验);

### 2.2 数据范围语义(演进口径)

| 层级(docs/03 旧口径) | 树化后语义 |
|---|---|
| L0 org 硬边界(既有) | **子树硬边界**:登录节点 N 的可见组织集 = N 自身 + N 的子树(org_path like);跨子树访问一律拒(122006 同码) |
| L1 归属可见(V2) | 节点内归属:数据行归属人 ∈ 可见组织集的人集合 |
| L2 部门范围(V2) | 即 L0 的子树语义本身(部门范围 = 部门节点子树),不再单列 |

- 管理员(admin)仍全树可见(既有旁路不变);
- fl-yy OrgScopeResolver(§三.2)的「登录组织→可见公司集合」在本模型下退化为一次 path 前缀推导,**不需要逐域 resolver**——范围统一在拦截器/查询基座算一次,各看板复用(比 fl-yy 六个 resolver 更收口);

### 2.3 目标域(addon-target)挂接

- 目标实体:`target_plan(org_id, …)`——org_id = **树上任一节点**(公司节点=全公司目标,分区节点=分区目标,部门节点=部门目标),达成率聚合 = 该节点子树的实绩汇总 ÷ 该节点目标值;
- docs/07 §2.1 三模型映射:战区分部目标计划 → target_plan(挂分区节点,config_json 存方案快照);阶段目标 → target_stage(plan 子表,stageKey+起止+多业绩线);提交留痕 → target_submission(who/when/快照);
- 「月目标独立于阶段目标」语义保留(两套并行,各自达成率);

## 四、非目标(显式排除)

- **不做「集团 / 分公司」两类公司实体**(裁决原文);跨树(多集团)场景 = 多棵树,当前单部署单树,V2 若需多集团再议;
- 不做组织树的历史版本/时间旅行(调整架构记录走轨迹/审计,不回溯历史归属);
- 不做 fl-yy 的北京专区类区域定制;
- 业绩预测模型(forecast_2026)只吸收方法论(财年季度/门店分类),脚本与凭证不搬(明文凭证是反面教材,方林侧应轮换)。
