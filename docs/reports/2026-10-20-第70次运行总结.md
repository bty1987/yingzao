# 第 70 次运行总结(2026-10-20):内核用户管理——建号/停用踢会话/重置密码 + Web Users.vue

> 无人值守接力。巡检(第 68 次)中浮出的真实闭环缺口:正式使用要「建立自己的账号体系」,但内核只有选择人查询(GET /api/users)与角色绑定——建号只能靠 SQL 脚本。本轮补齐内核账号面。

## 一、做了什么

### 1. 数据模型(V107)

- `yz_user` 加 `status` 列(0 启用默认/1 停用)——存量行行为不变。

### 2. 内核实现(零契约改动,内核端点自带守卫)

- **POST /api/users**(建号):管理员守卫(复用 requireAdmin 122003,对齐 roles/plans);用户名全局唯一查重 120101;密码 ≥6 位 120103;sha256 存储(与登录同算法);可选同组织角色绑定(insert..select 过滤 org,insert ignore 防并发);
- **GET /api/users/manage**(管理分页):关键字(用户名/显示名)+状态过滤+角色名 group_concat 聚合;
- **POST /api/users/{id}/status**(启停):停自己拒 120104(防锁死);**停用即时踢会话**——TokenStore.evictUser 移除该账号全部在管令牌(修「停用后旧令牌 12h 内仍有效」的内存令牌语义缺口);
- **POST /api/users/{id}/reset-password**:120103 校验+更新+踢会话(旧令牌全失效,重发需重新登录);
- **登录停用校验**:login 查 status,停用账号单独提示 120102「账号已停用,请联系管理员」(内部系统,明确提示优于含混);
- **既有 GET /api/users**(选择人数据源)收窄为仅启用用户——转交/指派场景选停用账号无意义;
- 错误码段 **120100-120105**(内核 100000-199999,120001 登录失败既有;段内空闲已核)。

### 3. Web(Users.vue + api 四函数 + /users 路由 + Layout 系统管理组「用户管理」)

列表(关键字/状态筛选+角色聚合列+分页)、新建账号弹窗(用户名/显示名/初始密码/初始角色多选,角色列表来自 listRoles 滤 admin)、启停(停用二次确认)、重置密码弹窗;停用按钮对自己禁用(服务端 120104 双闸)。

## 二、自主决策记录

1. **停用即时生效走 evictUser 而非每请求查库**:TokenStore 内存表 verify 零 DB 开销是现状性能姿态;停用/重置属低频管理动作,踢会话即时生效且语义清晰(重置密码踢旧会话同款);跨实例部署留 Docker/集群阶段一并评估(Redis 认证已在路线图);
2. **停用提示单独文案**(120102)而非并入「用户名或密码错误」:内部账号体系,泄露「账号存在性」风险低,管理员可诊断价值高;
3. **选择人数据源过滤停用账号**:行为收紧(更正确),既有冒烟用的全是启用号零影响;
4. **角色绑定在用户管理只做「初始角色」**:授权调整仍归「角色权限」页(单一职责);绑定仅接受同组织角色(insert..select org 过滤,防跨组织 L0);
5. 建号不设「删除」:账号留审计(与结算/轨迹同理),不用即停用。
