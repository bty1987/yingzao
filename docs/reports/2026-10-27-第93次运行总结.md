## 二、自主决策记录

1. **D3 一份 PRD 而非拆两份**:PK 全量进本 PRD(addon-target 落点清晰);战报部分按「划界」处置而非独立 PRD——其行业通用性成立但落地依赖 D4 驾驶舱专题口径与客源漏斗数据缺口,单独成 PRD 会是空壳;D6 拆两份的先例是两子域各有清晰 addon 落点,战报当前没有;
2. **模板+锁档合一为一张 target_pk_unit**:老 meeting_record 本就是 template 的锁档快照(1:1 by event+unit),两表 JOIN 无独立性收益;合一后「未锁=selected_tier 空」语义更直白,upsert 取代全删重插;
3. **五态而非老四态**:加「4 已作废」终态替代物理删(修 delete 无守卫家族,对齐营造「不物理删、留痕终态」惯例,同 sales_oales abate 收紧逻辑);归档仍只走定时快照链(手工 archive 恒拒语义保留);
4. **手工实绩全员可用而非仅公司级单元**:部门对赌是 PK 的本体场景,若只等单据归属模型则 D3 拍板后依然无法在部门级开赛;双轨=拍板即可用+自动聚合点亮不删代码;
5. **金标准矩阵/分组表/附件/推送全划界**:13→3 表的收敛底线——金标准本质是「默认值提示」,分组可被「上一届复制」覆盖,附件依赖未建的文件基建,推送依赖未建的通知中心;fl-yy 自身在这四处也各有死接口/双口径/硬编码债;
6. **draft_data 整包单列而非草稿表**:老 template_draft=eventId 单行 JSON 无状态无校验(缺陷),收敛为 event 行内列+org 守卫+仅 0 态可存,修缺陷不加表。
