# 第 83 次运行总结(2026-10-24):A3 批量收款 N:1

> docs/11 A 批第三项:一笔到账收 N 单——每笔一张子收据共享 batch_no,渠道行贪心拆分;分次支付聚合随渠道适配顺延。

## 一、做了什么

### 1. V802 迁移(一列一索引)

`payment_receipt` 加 `batch_no varchar(24) null`(批收组号,null=单笔收据现行为零变化)+idx_receipt_batch。老系统 FK-in-payment(srid/mrid 指一张收据)不抄:营造收据自带方向/金额/双人,批标识用组号。

### 2. BillService.collectBatch(先验后写)

- **先验阶段零写入**:逐笔守卫(活单 require)+顺序门控+Σ应收==Σ渠道,任一非法整批拒(修老「先 save 收据后校验」反模式的家族延续);
- **写阶段**:每笔一张子收据(1:1 与回执/confirm 链不变,占位插入+按 id 回填编号同款)共享 batch_no;渠道行按序贪心拆分(进循环先补货跳过耗尽渠道,拆不出零额行)——单张自洽 Σ渠道==该笔应收,整批渠道构成可由子收据行聚合还原;
- 逐笔条件更新并发闸+逐笔 PaymentCollectedEvent(eventKey 同单笔格式,Decoration/Sales/Demo 三消费者零改动);confirm 仍单笔两步复核(V1 口径)。
- 返回 {batchNo, receipts:[{billId, receiptId, receiptNo}]}。

### 3. 端点

POST /api/payment/bills/batch-collect {billIds[], channels[]}(两段路径与 /bills/{id}/× 无冲突);i18n 零新键(复用 param.invalid/badstate/channelSum/prevNotCollected 族)。

### 4. 分次支付聚合顺延(诚实边界)

老语义=渠道异步回调聚合(SUCCESS 累计==应收才完);营造 V1 无渠道回调(渠道适配=商业插件/C 批凭证),无回调即无分次——随渠道支付适配顺延,docs/11 划勾注明。

### 5. 跑数迭代(教训集中)

1. **require 第三参是 i18n 键不是拼好的消息**:批收混已收单守卫写 `require(..., "payment.bill.badstate:" + billId)`——拼接键不存在→NoSuchMessageException→全局处理器转 110000 系统繁忙(表象与业务码无关);修=手工 throw BizException(msg 纯键+":"+billId);
2. **db_exec 定义在 main 中部(3285 行)**:A3 段(1319)用=UnboundLocalError  entire 冒烟中断(第 74 次「前置段不可见」教训原文应验)——A3 DB 断言改段内独立 pymysql 连接(exactly-once 段同款);
3. **keepalive 僵尸抢场三连**:杀 pid 5577「没找到」(宿主机已重启过它)→杀 java 后 5s 内被抢起旧 jar(9936)持锁,fat jar clean 删不掉(mvn 失败)+rm busy——两轮净场(全杀 python+java→删 jar→重建)才建成功;铁律重申:**重启服务一律走 keepalive,杀场必须 python+java 一起清**。

## 二、自主决策记录

1. **每笔一张子收据+共享 batch_no**(非老式一张收据 N 笔 FK 回指):保住 1:1 回执/confirm 回填链与单张凭证完备性,批信息只是附加标识;
2. **渠道行贪心拆到子收据**:渠道行语义拆到「笔」而非挂「批」,每张子收据独立成凭证(对账/导出单张自洽),整批构成可聚合还原;
3. **分次支付聚合顺延**:无渠道回调即无分次触发器,硬造=过度设计;
4. 批收不新增错误码:270001/270003/270007/270010 全复用,混单明细进消息文本不进码。
