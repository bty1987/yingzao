## 二、自主决策记录

1. **组件=体系内基础件,不出三方向初稿**:AGENTS 前端审美流程针对「新页面」;组件锚定 App.vue 既有纸墨 token(方向已由 direction-approved.md 拍板),playground 是工程验收页非用户业务页面——不阻塞无人值守轮。视觉已按既有 cell/card/tag 语言延伸,截图亲验。
2. **人员联想本地过滤而非后端加 keyword**:GET /api/users 全量=组织内启用人数(小数据源),web 端同形态;后端零改动。
3. **yz-image-grid 与 yz-upload-image 分立而非合一**:编辑态(增删+上传状态)与只读态(详情回显)生命周期不同,分立组件各自简单;公共下载逻辑抽 utils/yz-file.js 消重。
4. **playground 放分包 pkg-base**:示范页非业务页面,分包承载主包零增长;顺带验证 subPackages+preloadRule 配置链,为后续业务分包铺路。
5. **扫码做成 utils 而非组件**:扫码是动作不是展示物,H5 显式降级(拒绝+提示)比静默失败诚实,业务页自行决定手动输入兜底。
6. **工作台临时入口**:R14 配置化宫格落地时该入口由槽位下发取代,注释已标明。

## 三、踩坑记录(下轮必读)

1. 🔴 **uni-app H5 编译后 `<input>` 变 `<uni-input>`**:class 落在外层 uni-input 上,真实输入框是其内部子元素——Playwright 定位要 `.yss .kw input` 而非 `.yss .kw input` 直接匹配(本轮 .yss .kw fill 三连败的根因)。
2. **uni-view 对 Playwright actionability 拦截超时**(第 66 次教训再现):统一姿势=evaluate `dispatchEvent(new MouseEvent('click', { bubbles: true }))` 程序化触发 + CUA 坐标点击二选一。
3. **uni-app H5 fullPage 截图出重复渲染伪影**(同内容 2 列×3 份):DOM 快照单份实证是截图器问题非页面 bug——移动端页面一律分段视口截图。
4. **vite HMR 对组件模板修改热替换后,页面状态(面板开合)不可靠**:改组件后 reload 页面再验。
5. toast 残影会混入下一张截图(uni-toast 1.5s 自动消失)——截图前等 2s。
