## 二、自主决策记录

1. **计划与事件双设施分工显式化**(类注释):广播(事件)vs 待办(计划)是两种调度语义,不合并——老系统 messagequeuing(通知)与 plan(任务)混用导致 44% 丢失的教训反面印证;
2. **处理器=进程内 Spring bean(V1)**:老外部 Python 执行器是部署形态不是模型;HTTP 回调型任务留 V2 对接口,先让内核设施被插件用起来;
3. **计划可取消(4)**:事件不可取消(已发生的事实),计划是未来待办可撤——所以状态机多一态;
4. **claim 补到期检查**(冒烟抓出的真产品 bug):dispatchDue 有 `next_run_time<=now()` 而单条 dispatchPlan 入口没有——afterCommit 立即派发会把「runAt 明天」的任务当场跑掉;修=claim SQL 统一加到期谓词;
5. **提交走 REST 仅为管理面**:防止业务绕过插件直调把计划当 RPC 用,业务姿势收口在 SPI。
