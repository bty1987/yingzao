## 八、教训沉淀

1. **类内多测试共享同库+delete 后 H2 自增不归零**:第二个测试起 auto id≠1,而服务侧按 id=1 取人(displayName/requireOrgUser)落空——表象是「单测单跑绿、全类跑挂」;解法=测试数据显式 id(ApprovalServiceTest 先例);单跑复现不出来时优先怀疑「同库跨用例状态」,不是并发;
2. **python -I 吞 PYTHONIOENCODING**:隔离模式忽略环境变量,GBK 控制台下冒烟脚本 ✓/✗ 必炸——仓内自有脚本去掉 -I 或改 `-X utf8`;
3. **stub 完整性靠编译器**:契约接口新增方法(W1/W2 已扩 DecorationApi/QuotationApi/GoodsApi)用旧 grep 模式清点会漏——直接以「编译错误=权威清单」收口,别靠记忆;
4. **最小列面表要对 load 查询逐列核对**:`select *`(sales loadSale)安全,显式列单(quotation load 的 material_package_id[V402])必漏——建表前先抓服务内全部 select 列清单;
5. **uk 冲突在多行测试数据里埋伏**:quotation_norm_item uk 含 source_id,同键多行必须逐行独立——测试数据自造要过一遍唯一键清单。
