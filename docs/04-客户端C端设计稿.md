# 04 - 客户端(C 端)小程序/H5 设计稿

> 状态:**排期已定(2026-10-14 用户拍板),本文档为阶段 A 开工前的 L1 设计底座**;按 2026-10-12 解除门闸纪律按推荐口径推进,如有异议随时打回。
> 定位:对外客户触点(微信小程序 + H5,同一 uni-app 工程 `web-mp`),与员工端 `app/` 并列,同一后端零分叉。

## 1. 范围与非目标

**首版四页闭环**:

| 页面 | 认证态 | 数据源 | 说明 |
|---|---|---|---|
| 登录 | — | 手机验证码 | 唯一入口;验证码经通知中心转告(dev 可取),短信通道 V2 |
| 官网案例库 | 匿名可看 | addon-market Showcase | 只读露出口(见 §3),城市/案例/人物/效果图 |
| 施工进度 | 登录 | addon-construction | 按装修单绑定校验的**脱敏视图**:节点进度时间轴;不含金额/人员/联系方式 |
| 会员积分 | 登录 | addon-member | 客户本人积分账户只读(余额+流水摘要) |

**非目标(V2+)**:在线支付、客服 IM、保修/投诉工单、C 端报价器、积分兑换下单(C 端只读,兑换走门店/员工端代客)、客户档案自助编辑(改名/换手机走员工端)。

## 2. 认证模型(核心设计)

### 2.1 身份分域

- C 端用户 **≠ `yz_user`**(员工账号体系互不污染);C 端身份锚 = **customerprofile 手机号**(主数据底座,一人一档,HMAC 等值检索);
- 登录 = 手机验证码验证通过 → 客户档案 **get-or-create 最小档案**(customerprofile 唯一写点纪律保持,C 端登录即显式写点;修老 existCustomer 窄口径的多档风险:以 org+active_hmac 唯一键兜底);
- 手机号属 PII:C 端令牌只携 customerId/orgId,不携明文;任何取手机号的接口走 reveal 留痕(既有纪律)。

### 2.2 令牌

- 复用内核 token 形态,payload 增主体类型:`principal=customer` + `customerId`/`orgId`(员工 token 现状=`principal=user`+`userId`,向后兼容);
- 有效期与刷新策略与员工端一致;C 端令牌**只可能访问显式声明为 C 端的端点**(见 §3),拿它调任何员工端点一律 122006 拒——越权面收口在拦截器一处。

### 2.3 验证码

- 6 位数字,5 分钟有效,单次消费;同手机号 60s 限发 + 单日上限(内核简单限流,超限 110 段新码);
- 投递:通知中心转告(员工端/冒烟可代取)→ 短信 Provider 扩展点(V2,凭证外部依赖)。

## 3. RBAC v2 第四型/第五型(api 段声明扩展)

现三型:`菜单 path` / `capability` / `authenticated`。新增:

| require | 语义 | 典型端点 |
|---|---|---|
| `anonymous` | 免认证直放(enforce 下也放行,静态完备性校验纳入) | 案例库匿名浏览聚合口 |
| `c-customer` | 须 C 端令牌(principal=customer),且校验资源归属 customerId | 进度/积分/本人信息 |

- 内核 RbacService/拦截器小改:admin 旁路不适用 C 端令牌(C 端令牌非 admin);`c-customer` 端点对员工令牌放行与否→**不放行**(端点口径属 C 端,员工看数据走管理端);
- enforce 模式下未声明即拒的既有纪律不变;smoke_enforce 静态完备性样例扩 C 端组。

## 4. 端点清单(首版,全部只读 + 登录)

| 端点 | require | 说明 |
|---|---|---|
| POST /api/c/auth/code | anonymous | 发验证码(限流) |
| POST /api/c/auth/login | anonymous | 验证码换 C 端令牌(get-or-create 档案) |
| GET /api/c/cases | anonymous | 案例库聚合(城市/案例/人物/图,Showcase 只读投影) |
| GET /api/c/progress?orderId= | c-customer | 装修单进度脱敏视图(归属校验 customerId) |
| GET /api/c/points | c-customer | 本人积分账户+流水摘要 |

- 归属 `c` 前缀 = C 端专用聚合面(各 addon 禁自开匿名口,聚合口统一挂在一个薄插件或内核?**推荐:新薄插件 `addon-portal`**(码段 360000 建议),聚合口在此,经 addons-api 只读契约取数(market/construction/member 零改动),与"插件间只走契约"军规一致);
- 错误码段:portal 360000(360001 验证码错误/过期、360002 限流、360003 档案手机号不符、360004 非本人装修单等)。

## 5. 前端工程(web-mp)

- uni-app + Vue3,复用 `app/` 骨架与方向三 token(纸白/墨黑/朱印);小程序 + H5 一码双出;
- 登录态存本地Storage,401 → 登录页;请求层区分 anonymous 页(无令牌也可进)与登录页;
- 不做 tabBar 登录墙:案例库可匿名逛,进度/积分点进再登录(转化漏斗常识)。
