## 一、方林钉钉端形态速写(它是什么)

**一个 ERP 后端,三个前端载体**:

| 载体 | 技术 | 状态 |
|---|---|---|
| `Public/` 旧版 H5 | 静态 HTML + `.fl` 模板 + Zepto/SUI + `$("#dtalkContent").load()` 片段路由 | 生产在跑;19 个模块入口页 = 19 个钉钉应用入口 |
| `Vuer/` → `Public/vue` | Vue3 + Vite + TS + Vant + Pinia,hash 路由,63 条路由/68 个视图 | 104 条旧页映射全部"已构建",处于生产验收期;新旧**模块级共存**,`version-switch.fl` 双向跳转 |
| `Applet/` 钉钉原生小程序 | 支付宝系 DSL(.axml/.acss) | 仅"扫码登录确认"一个动作的早期实验,与主线脱节,归档 |

**免登链路**(全链曾经同步 AJAX,Vue 版已异步化):

```
dd.config(签名由 requestDDConfig.do 按 URL 下发,签名 URL 取 location.href 去 # 后部分)
→ dd.runtime.permission.requestAuthCode(corpId)
→ communionServer/queryDDUserInfo.do {code, company} → user.userid
→ communionServer/requestAuthCode.do {userId, code, secret} → authentication(业务令牌,后续每个请求 body 携带)
```

**多应用入口模型**:一个功能域一个钉钉应用(AgentId),config 里 7 个 AgentId(approval/supervision/login/salesman/assis/design/fip);入口页各自 `Ding.handle(agentId)`,角色差异靠"不同的人加入不同的钉钉应用"实现。

**接口风格**(Struts 系):`.do` 后缀根路径;POST 表单 + 点号参数(`paging.page`、`decorationPicture.orderId`);响应 `{errorCode, errorMsg, ...}`;分页 `paging.page`(1 起)/`paging.rows`;金额/面积按 ×1000 整数存储,前端 tranargs 声明字段自动换算;上传走 `uploadImg.do`(multipart `strutsUploads`)与钉钉媒体直传(`dd.biz.util.uploadImage`)双链路并存。

### 各域要点与回溯指针(接口为 `.do` 原名)

**1. 施工域**——最重的域,约 30 个接口。角色差异**按接口三分**:`pageConstruction.do`(工程部)/`pageConstructionForSupervision.do`(监理)/`pageConstructionForQualiter.do`(质检)。详情页八 tab(款项/报价/主材/增减/辅料/外辅/选材/人员)按需加载。节点操作:`beginConstructionSchedule.do`/`finishConstructionSchedule.do`/`enterConstructionSchedule.do`/`leaveConstructionSchedule.do`;日记 `addConstructionDiary.do`(文字+钉钉图片);人员 `queryConstructerByOrderId.do`/`addConstructer.do`/`sendConstructer.do`;附加项 `queryNormriceItemByType.do`/`addNormriceItem.do`;图纸 `queryConstructionDrawingByCid.do`/`addConstructionDrawings.do`/`queryDecorationPictureByOrderId.do`。进度枚举 15 级(初始→开工→砌墙→…→水电验收→保洁),进度条配置下放静态 JSON(`Public/json/construction.json`)。

**2. 审批域**——19 个流程模板以**静态 JSON schema** 下放(`Public/json/approval.json`):每模板含钉钉 PROC-* processCode、字段分组、字段类型(`query`=装修单号触发预填/`filling`=从装修单对象自动带出/`text`/`textarea`)、订单类型与施工进度枚举。操作 `approveApproval.do`/`refuseApproval.do`/`submitApprovalForDing.do`;列表 `pageApprovalForReceive.do`/`pageApprovalForSend.do`。

**4. 销售域**——创建销售单两步(装修单校验+品牌 → 商品明细,联想接口 `queryUserByPinyin.do`/`queryVillageForNameByPinyin.do`/`queryGoodsByName.do` 系列);款线 `addSalesPaymentForDeposit.do`/`ForFullpay.do` + 对应 cancel;状态枚举下放 `Public/json/sales.json`。

**5. 款项域**——收款码 URL 拼接 `fanglin.vip/wx/wxpay?orderId=..&paymentType=..`(前端 qrcode 生码,客户微信扫码进 H5 付款);`alipay.do` 返回 URL 入 iframe;`queryConstant.do`(module=payment)取常量。

**6. 辅料/外辅域**——辅料:定额带出(`queryNormriceItemByType.do`+`makeNormtion.do`)→明细数量校验(`checkAccessoriesItem.do`)→建单(`addAccessories.do`)→发货(`deliveAccessories.do`)/撤销;外辅:`addOccessories.do`(含监理带出、费用模板、`amountOccessoriesItem.do` 定额已用量)、`deliveOccessories.do`/`receiveOccessories.do`/`rateOccessories.do`。

**9. 信息域**——活动票 `createVticket.do`/`countVticket.do`(param=0 票数/1 到场/2 注册排名);电话 `queryCustomerForPhone.do` 取主叫+`phoneCall.do` 拨打。

报修受理(依赖 11 号 B1 addon-service);工人工费查询(addon-salary 商业);人员电话本(只读+拨号);请假之外的行政流。

### 4.4 移动端接口契约原则(从方林教训反推)

1. **角色差异不造三个接口**:方林按角色分 `pageConstructionForSupervision/Qualiter` 三接口,营造一律**一个接口 + 数据范围**(docs/03/08 基座),前端不感知角色;
2. **金额不 ×1000**:方林 tranargs 整数换算是历史包袱(DECIMAL 不可用的年代产物),营造 DECIMAL 直传,移动端不引入任何换算层;
3. **令牌走 header 不走 body**:方林每请求 body 带 authentication,营造 Bearer header(app 已如此),免登链路换发同一 token;
4. **分页约定统一** `page/rows`,移动端列表全部 onReachBottom 累加;
5. **枚举一律接口取**:不建 `Public/json/*.json` 式前端静态配置(双源 + 发版同步问题,方林新旧两份 JSON 已现不一致风险);
6. **操作接口幂等**:开工/完工/发货类动作带状态前置校验(后端),前端不做状态闸门以外的判断。

## 五、内核企微/钉钉适配器开发需求(批次 C4 的落地输入)

11 号文档批次 C4"企微/钉钉 H5 免登 + 通知订阅(宿主凭证)"动工前,按方林二十年经验定这几条:

1. **免登链路**(钉钉为例,企微同构):宿主容器内打开 `/app/` H5 → 前端取宿主 authCode → **后端**用 appSecret 换 userid → 映射 organization 内账号 → 签发 yingzao token → 进同一套页面。**secret 只能在后端**——方林三处前端硬编码 secret(两份 H5 config + 一份小程序)是 P0 级事故遗留,营造军规级禁止;
2. **签名服务**:`dd.config` 签名由后端按 URL 下发(签名 URL = `location.href.split('#')[0]`,hash 路由天然免 fallback;query 参与签名时注意编码一致性——方林 README 专门提醒过);
3. **JSAPI 抽象**:内核提供宿主桥(拍照/选图/预览/扫码/定位/分享),宿主差异封装在适配器内;`app/` 业务代码只认统一 bridge,不 import 任何 dd./wx. 全局——这是 uni-app 一码多端与"宿主 H5 免登进同一页面"能成立的前提;
4. **运行时配置模式**:方林 `runtime-config.js`(部署期改宿主 AgentId/host 不重编译)思想可抄——营造宿主凭证/appid 用**部署期注入的 env/配置文件**,不写死构建产物;
5. **通知订阅**:审批待办/节点完工/款项到账 → 宿主工作通知;通知中心 payload 带 entity 路由(与 P1-5 同一件);
6. **扫码登录确认**:方林"PC 端出示二维码 + 手机确认登录"(`updateLoginInfoForAuthentication.do` + 小程序确认页)是通用 SSO 场景,内核认证域留扩展点(低优先)。

## 六、工程定式与避坑(直接抄 / 反模式)

**直接抄的定式**:
- **模块级新旧共存灰度**:旧页注入"新版"浮动按钮跳 Vue 路由,Vue 顶栏"旧版"按钮按 `legacy=<模块名>` 参数回旧入口;约定"从旧到新必带 legacy 参数、回去时不能只按当前路由推断"(施工/监理/质检三角色共用一个路由但须回各自入口)。营造 web/移动端大改版时可复用此模式;
- **详情页 tab 按需加载**:八 tab 只在点开时拉数据,移动端流量友好;
- **联想输入统一接口**:`queryUserByPinyin`/`queryVillageForNameByPinyin`/`queryGoodsByName` 一域一联想接口,移动端搜索体验的关键;
- **表单 schema 下放 + 预填钩子**:审批 19 流程模板一个 JSON 覆盖,`query`(装修单号触发预填)/`filling`(对象自动带出)两类钩子思想直接进 P0-2。

**反模式(方林踩过,营造禁止)**:
- 前端硬编码 secret(三处);HTTP 明文接口与 SDK;同步 AJAX(async:false,免登链路尤甚);
- 全局 `param` 大对象跨页传参(隐式耦合,重构成本最大来源——方林为此写了 param→store 映射表);
- `#dtalkContent.load()` 片段路由(无路由/无状态/无构建体系,是 Vue 重构的全部动机);
- 金额 ×1000 整数存储 + 前端声明式换算;
- 一功能一宿主应用(入口碎片化);
- config 缺定义靠 URL 兜底(方林 4 个入口页引用了 config 里不存在的 AgentId,靠 `?agent=` 救)——营造配置缺失必须显式报错。
